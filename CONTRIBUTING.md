# Public issue quality gate

1. Reproduce the problem against **original Cloudroom**, not only a custom distribution.
2. Check original Cloudroom issues and pull requests before creating duplicates.
3. Recreate with wholly synthetic data and no private file names/paths, internal company workflows or raw logs.
4. State exact upstream SHA or release, environment, steps, expected and observed behavior, and any minimal regression test.
5. Submit through a human reviewer who inspects content for **semantic leakage** beyond automated secret patterns.
6. Cross-link any useful upstream issue/PR. Follow original Cloudroom maintainer instructions and feedback; do not claim partnership or official standing.

**No automatic publication pipeline.** Defects discovered privately remain private until cleared. Report security vulnerabilities through Cloudroom's private security process.
